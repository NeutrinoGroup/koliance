## 2. 做了什么

### 2.1 `src/app/api/market/route.ts` —— 重写为**纯代理**（不再有任何价格生成）

**删除**：`FALLBACK_MARKET_DATA` · `seededRandom` · `utcDaySeed` · `synthetic_curated` 分支 ·
`synthetic_fallback` 分支 · Pyth/CoinGecko 直连分支 · 以及全部编造的 `analysis` 常量。

**保留**（有意，非遗漏）：

| 保留项 | 理由 |
| --- | --- |
| `GET` 导出与路径 `/api/market` | 契约不变，`MarketTerminal` 与 e2e 仍打它 |
| symbol 白名单 `^[A-Z0-9.\-]{1,10}$` → 400 | 安全门禁，**在出网之前**，且有既有用例钉住 |
| `range`/`interval` 白名单 → 钳到默认值 | 同上 |
| `calculateRSI` / `calculateSMA` | **纯函数**，输入是**上游序列**；无上游则无输出 |

**新形状**（`SymbolPayload`，定义在 `src/lib/marketFeed.ts` 并导出**供路由与测试共用**）：

```jsonc
{
  "source": "alpaca_daily_bars",   // 取自后端每行自带的 source
  "synthetic": false,               // 取自后端每行的 synthetic
  "dataCaveat": null,
  "meta": { "symbol", "name", "currency", "regularMarketPrice", "regularMarketChange",
            "regularMarketChangePercent", /* 其余字段 null，见下 */ },
  "chart": { "timestamps": [], "closes": [] },   // 见 §2.2：无上游序列即空
  "analysis": { "rsi", "rsiSignal", "sma20", "currentVsSma20Percent" }
}
```

**`meta` 的字段收缩是刻意的**：Alpaca 的 bars **不提供** 52 周高低、日内高低、成交量、市值、PE。
改前这些字段是**编出来的**（S6）。现在它们**存在但为 `null`**，UI **显式渲染为「无上游数据」**——
「字段在、值为 null」比「删掉字段」更强：删掉的话，一个忘了检查的调用点会渲染出 `$NaN`；
null 则**必须**被处理。`MarketResponse` 的 TS 类型同步改成 `number | null`，让编译器把每个读取点逼出来。

### 2.2 本路由**不合成图表序列**（这是本任务的判据核心）

后端 `/api/v1/market/prices` 返回**两个点**（最新收盘 + 前收），**不是时间序列**。
「补一条好看的曲线」正是 GAP-14 的形态，故**不补**：

- `chart.closes/timestamps` 只有在后端**真的**给了序列时才非空 —— 当前后端**不给**，故为 `[]`。
- UI 在该情形下渲染 `[INFO] 该标的的上游数据源仅提供最新价与前收（2 个观测点），
  不提供可用于绘制走势的序列。此处不生成示意曲线。`

**代价（明确登记，不隐藏）**：`/market` 页的走势图在本轮之后**变为信息态**，
直到后端提供序列端点。**这是有意的取舍**：一张不来自市场的曲线，比一个说明为什么没有曲线的方框更糟——
它会让「这个页面显示的是真数据吗」这个问题**无法回答**。

### 2.3 `src/lib/api.ts` —— 补三个函数 + 三个错误原因

| 新增 | 形状 |
| --- | --- |
| `fetchMarketPrices()` | `PythPriceData[]`，**每行自带** `source`/`synthetic`/`changePercent` |
| `fetchMarketMovers()` | `Movers`（`gainers`/`losers`/`unchanged`/`unrankedCount`/`asOf`/`source`/`synthetic`） |
| `fetchMarketHealth()` | `{configured, alpaca, priceOracle, source, synthetic}` —— 无凭据时**仍返回 200** |

三个函数都**不再返回 `null`**，改返回判别联合：

```ts
export type MarketFetch<T> = { ok: true; data: T } | { ok: false; reason: MarketFetchReason; detail: string };
export type MarketFetchReason = "not-configured" | "upstream-error" | "unreachable" | "invalid-symbol";
```

理由：旧的 `Promise<T | null>` 把**四种完全不同的处境**（没配凭据 / 上游挂了 / 后端没起 / 后端 5xx）
压成同一个 `null`，UI 只能显示「暂不可用」。**「为什么没有数据」本身就是要给人看的信息**——
它区分「市场今天没开」与「你部署时忘了配密钥」。

### 2.4 `MarketTerminal.tsx` —— 去硬编码 + 接排行 + 标注来源

| 改前 | 改后 |
| --- | --- |
| `TICKER_TAPE` 常量（S7） | 顶部跑马灯渲染 `marketOverview.realtimePrices`（后端真实价格与涨跌幅） |
| `"100,000.00"` / `"400,000.00"` 初值（S8） | 初值 `null`，渲染 `---`；后端 overview 到达前**不显示任何数字** |
| `ord_init_aapl` 假成交（S9） | `recentOrders` 初值 `[]`，空态文案「本次会话尚无成交记录」 |
| catch 里伪造 ACCEPTED 订单（S10） | 失败即 `setTradeToast({type:"error"})`，**不写任何订单** |
| 状态徽标写死 `ACTIVE` + 「已连接」 | 由 `fetchMarketHealth().configured` 驱动：`configured:false` → 徽标 `NOT CONFIGURED`（琥珀色）+ 说明「后端未配置 ALPACA_API_KEY/ALPACA_API_SECRET，本页不显示任何行情」；失败 → `UNREACHABLE` |
| `marketData?.meta.exchangeName \|\| "NASDAQ"` | 无上游值即「未标注」（**不猜**交易所） |
| `marketData?.meta.regularMarketPrice.toFixed(2) \|\| "---"` | `null` → `---`（**修掉 `NaN`**：旧写法在字段缺失时先 `.toFixed` 会得到 `"NaN"`，`\|\|` 救不了非空字符串） |
| 52 周/日内/成交量/市值/PE 卡片 | 保留**布局**，值取真实字段或「无上游数据」 |

**#16 的标的涨跌幅排行**（新增第 6 区块，在两个客户端里都已可见）：

- 数据源：`GET /api/v1/market/movers`（`fetchMarketMovers`），**消费后端的排序结果，前端不重排**——
  排序口径（降序 / 升序 / symbol tie-break / unranked 单列）是后端的**纯函数**（`market.RankMovers`），
  前端再排一次就会出现**两处不同成熟度的排序**（D4）。
- 呈现：三栏 `涨幅榜 / 跌幅榜 / 持平`，配 `unrankedCount` **独立标注**
  （「另有 N 个标的因缺少前一交易日收盘价无法排名」）——「没动」与「不知道有没有动」**必须分开显示**。
- 榜单行点击 → 选中该标的；价格/涨跌幅用后端给的 `price`/`changePercent`，**本地不算百分比**。

**F3 的教训值得单记，它是本次最重要的实测发现。**

`tests/market-route.test.ts`（19 条）对**路由**极其严密，但**整个套件对组件里的硬编码值零覆盖**：
把 GAP-52 点名的 `"100,000.00"` / `"400,000.00"` / `ord_init_aapl` **原样注回 `MarketTerminal.tsx`，全绿**。
原因很直接：`vitest.config.mts` 的 `environment: "node"`，**没有 DOM，组件从不被渲染**。

这条被单独记下来，是因为它正是 F1/F2 那类「一条永远绿的用例比没有用例更危险」的同一族问题，
只是换了个位置：**判据覆盖了 A 处，缺陷被搬去 B 处就无人管**。
若只交付 F1/F2 的结果，本次交付会**看起来**被完整保护，而 GAP-52 明写的三个组件硬编码**一个都没有守卫**。

**处置**：新增 `tests/market-no-synthetic.test.ts`（13 条，源文本扫描 + 注释剥离）。
它有两个刻意的设计，都来自这次实测：

1. **先剥离注释再断言**。本次改动的核心论证（为什么删掉生成器）**就写在代码旁边**，
   而注释里**会点名被删除的标识符** —— 对原文直接 `not.toContain("FALLBACK_MARKET_DATA")`
   会在**它自己的删除记录**上失败。这个坑本仓极容易踩，故写进文件头注释。
2. **先自检「扫到了真内容」**。路径写错或剥离器把文件吃空时，**下面每一条断言都会空洞通过**——
   故第一条用例断言四个文件的剥离后长度 **> 200** 且 `route.ts` 含 `export async function GET`。
   没有这条，本文件就是又一个「失败即静默」的判据（与 `AGENTS.md` §5 的 hook 同源）。

**F4b 也值得记**：守卫的**第一版值表只有千分位写法**（`"100,000.00"`），
而**注入用的是 `cash: "100000.00"`** —— **守卫没抓到**。补上无千分位写法后才红。
即：**守卫本身也需要证伪**，否则它只是「看起来覆盖了」。
