## 1. 缺陷（`docs/changes/029` §3.1 的复述，非本记录新发现）

`market_test.go` 的负向判据是**禁词表**（子串扫描）：

```go
for _, forbidden := range []string{"150", "TSLA", "realtimePrices", "gainers", "feedId"} {
    if strings.Contains(body, forbidden) { ... }
}
```

`qa-validator` 的 F2 注入 —— **503 的体内夹带 `lastKnownRegularMarketPrice: 999.99`** ——
**一个禁词都没命中**，故实现方用例全绿：

| 现有断言 | 注入后是否仍满足 |
| --- | --- |
| 状态码 == 503 | 满足（对） |
| 体内含 `ALPACA_API_KEY` | 满足（对） |
| 不含那 5 个子串 | 满足 —— **这个价格字段不在表上** |

这正是要防的形态：一个「把昨天收盘价当『最近已知行情』随 503 一起返回」的实现，
**逐条满足**上面的判据。issue #14 的契约是「拒答体里零价格字段」，禁词表只是它的一个**近似**。

## 2. 改法：禁词表 → 性质（形状）

新增三个测试内助手（`market_test.go` 内，非生产代码）：

| 助手 | 作用 |
| --- | --- |
| `jsonTree(t, label, body)` | 用 `UseNumber` 解码，返回**原始 JSON 树**与**树中每一个 JSON 数字**（含嵌套在数组/对象里的） |
| `assertRefusal(t, label, body)` | 一条拒答的**形状**判据，见下 |
| （`assertRefusal` 内的键集合检查） | 顶层键**恰好是** `["error"]` |

`assertRefusal` 断言四件事：

1. **顶层键恰好一个，且就是 `error`** —— `lastKnownRegularMarketPrice`、`realtimePrices`、`gainers`、
   `meta`……**任何一个键**都是「没有数据却把行情送到了调用方」。枚举「我们想得到的键」抓不到「我们没想到的那个」。
2. **体内不含任何 JSON 数字**（递归遍历整棵树，**非仅顶层**）。
3. **`error` 的值必须是 JSON 字符串** —— 堵住「把价格塞进 `error` 的字符串里」这条路：
   裸数字是「贴了安心标签的价格」，写进文案的数字是「穿了句子的价格」。
4. **含 `ALPACA_API_KEY` 的必需事实**（任务要求**保留**，未削弱）：断言为**性质**（存在一条错误消息**含**该变量名），
   而非钉死 `jsonError` 的文案 —— #14 的目的是让调用方知道**为什么**拿不到数据。

**保留的原有断言**：503 状态码（三条读路径 + trade/close）· `"success"` 子串（trade）原样未动。
**新增覆盖**：`trade` / `close` **原来只断言状态码，本次补上拒答体形状断言**（响应体才是客户端渲染的东西）。

**未改 `market_edge_qa_test.go`**（`qa-validator` 的独立用例）：它已是性质断言。
洞在**实现方**的判据里，改它才是本次范围。

**这条对照当场抓到了我自己的一个失明**：第一版测量器假定响应体是 JSON **对象**，而 `/api/v1/market/prices`
返回的是**数组** —— 它在 `--- FAIL: ... refusal body is a []interface {}` 上立刻变红。
若无此对照，一条「只对对象体有效」的判据会在**数组体端点**上静默失明。故测量器**按端点两种形状都验**。
