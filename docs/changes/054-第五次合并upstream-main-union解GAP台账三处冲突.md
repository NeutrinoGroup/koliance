| 侧 | 内容 |

**解法**：**取并集**，并把**两侧各自已经过时的自指陈述改成与文件实际枚举一致**：

- 编号核对块 → 按本次重测改写（见 §3）。

> **为什么必须改这几句**：它们是**自指陈述**——说的是"本行与文件自身枚举一致""某分支仍未合并"，
> **错了不会响**：没有任何测试会失败（`AGENTS.md` §8 的「自指陈述」条）。
> 其中**上游那两句（"仍未消解""等 #38 填入"）恰恰被本次合并亲手作废**，

## 3. 编号核对（D4 / `AGENTS.md` §6）——**本次无撞号，未重编任何号**

### 3.1 核对口径（**逐 ref**，**不用 `git log --all --name-only`**）

```
git -C <repo> for-each-ref --format="%(refname)" refs/heads refs/remotes     # → 34 个 ref
# 逐 ref：
git -C <repo> grep -h -o -E "GAP-[0-9]+"  <ref> -- docs/
git -C <repo> grep -h -o -E "^### 5\.[0-9]+" <ref> -- docs/GAP台账.md
git -C <repo> ls-tree -r --name-only      <ref> -- docs/changes/
```

> **为何不用 `git log --all --name-only`**：它默认**简化 merge**，**不能据"列不出"判定文件/号不存在**——
> 口径本身不可靠（`docs/error-handling-adr` 的取号注与 `docs/changes/053` §3.1 都记过同一条）。
> **另一条**：`GAP-\d+` 的命中**不只有"登记"**——正文里的**区间字面量与交叉引用**（如「`GAP-65~71`」）也会命中。
> 故并集只用于**判"某号是否出现过"**，**不用于判"某号是否被登记"**。
