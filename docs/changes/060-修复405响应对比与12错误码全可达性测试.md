# 060 - 修复 405 响应对比与 12 错误码全可达性测试（Step 2.2）

- **状态**：已完成
- **日期**：2026-10-13 (UTC)
- **关联**：`docs/adr/ADR-006-统一报错处理体系.md` · `docs/changes/059-ADR006错误体系基建与安全加固.md` · issue #33
- **作者/执行**：backend-dev (Go / 后端工程专家)

---

## 1. 改动背景与目标

依据 ADR-006 与执行任务指令，完成以下两项任务：
1. **修复 `reqlog_test.go:242-251` 中的 "DELETE 405 from methodOnly"**：
   在 `middleware.go` 中 `methodOnly` 接入了 `writeError`，响应体升格为包含 `requestId` 的标准信封。在 `TestLoggingMiddlewareDoesNotAlterBody` 的该测试用例中，`bare` 处理未经过 `loggingMiddleware`，默认上下文无 `requestId`；而 `wrapped` 会生成/携带 `requestId`，导致 `responseDiff` 判定 body 不一致。在 `tc.req()` 中通过设置 `X-Request-Id` 请求头并注入 `ctxKeyRequestID{}` 上下文（如 `"dummy-req-id"`），使 `bare` 与 `wrapped` 保持一致的 `requestId`，从而通过 P4 判据断言。
2. **在 `errors_test.go` 中新增 `TestEveryErrorCodeIsReachable` 测试**：
   针对 ADR-006 §3.6.2 定义的全部 12 个 `ErrorCode`，通过真实路由与构造 handler 触发 HTTP 错误响应，严格断言：
   - HTTP 状态码符合 ADR-006 定义（400, 401, 403, 404, 405, 429, 500, 501/503, 502, 503）；
   - 响应头 Content-Type 为 `application/json`；
   - 响应体 JSON 严格包含对应的 `code` / `errorCode` 与不可篡改的业务文案 `error`；
   - 包含非空 `requestId`；
   - 全部 12 个枚举项均被覆盖且可达（满足 §4.1 P3 与 N4 防死代码要求）；
   - 增加 `writeError` 针对 12 个错误码的标准 3-key 闭集信封合约契约测试。
3. **本地验证**：
   运行 `go test -v -race -count=1 ./internal/httpapi/...` 确保 100% 通过。

---

## 2. 详细实现记录

- `backend/internal/httpapi/reqlog_test.go`:
  - 调整 "DELETE 405 from methodOnly" 用例的 `req` 构造，添加 `X-Request-Id: dummy-req-id` header 及 `ctxKeyRequestID{}` context 值。
- `backend/internal/httpapi/errors_test.go`:
  - 引入 `context`、`fmt`、`log/slog` 及 `github.com/koliance/backend/internal/verifier`；
  - 添加 `TestEveryErrorCodeIsReachable` 测试函数，覆盖全部 12 个 ErrorCode：
    - `INVALID_REQUEST`: 调用真实路由 `GET /api/v1/liquidations?limit=-1` (400)
    - `INVALID_PROOF`: 调用真实路由 `POST /api/v1/verifier/verify` 注入 `ErrInvalidProof` (400)
    - `UNAUTHORIZED`: 调用真实路由 `GET /api/v1/agentcard/cards/card-test` 无 token (401)
    - `QUOTA_EXHAUSTED`: 构造 handler 触发 `CodeQuotaExhausted` (403)
    - `RESOURCE_NOT_FOUND`: 构造 handler 触发 `CodeResourceNotFound` (404)
    - `METHOD_NOT_ALLOWED`: 调用真实路由 `DELETE /api/v1/liquidations` (405)
    - `RATE_LIMITED`: 构造 handler 触发 `CodeRateLimited` (429)
    - `INTERNAL_ERROR`: 构造 handler 触发 `CodeInternalError` (500)
    - `VERIFIER_UNAVAILABLE`: 调用真实路由 `POST /api/v1/verifier/verify` 注入 nil verifier (503)
    - `UPSTREAM_UNAVAILABLE`: 构造 handler 触发 `CodeUpstreamUnavailable` (502)
    - `DATABASE_UNAVAILABLE`: 调用真实路由 `POST /api/v1/game/proof` 注入 nil DB (503)
    - `SERVICE_NOT_CONFIGURED`: 调用真实路由 `GET /api/v1/market/prices` 注入未配置 Alpaca 凭据 (503)
  - 逐一断言 HTTP 状态码、信封字段、闭集文案及非空 request ID，并断言全集覆盖；
  - 增补直接 `writeError` 针对 12 个错误码的标准 3-key 信封字段严格断言。
