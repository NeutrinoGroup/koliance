### 3.2 闭集强校验与非法 Code 强制 Fallback 及告警审计
- **实现核查（`backend/internal/httpapi/errors.go`）**：
  - `sanitizeErrorCode` 通过 `slices.Contains(AllErrorCodes, code)` 判定枚举有效性；
  - 遇到未知/非法 code 时，触发 `slog.WarnContext` 输出带有 `illegalCode` 与 `requestId` 的结构化告警日志；
  - 强制纠偏返回 `CodeInternalError`；
  - `writeError` 与 `jsonEnvelopeError` 在编码输出前统一经 `sanitizeErrorCode` 过滤。
- **测试核查（`backend/internal/httpapi/errors_test.go`）**：
  - `TestWriteErrorAndJsonEnvelopeErrorFallbackOnIllegalCode` 分别对 `writeError` 与 `jsonEnvelopeError` 注入非法字符串 `"UNKNOWN_ILLEGAL_CODE"` 与 `"UNKNOWN_ILLEGAL_CODE_2"`；
  - 实测输出精准告警日志：
    ```text
    WARN illegal error code outside closed set; falling back to INTERNAL_ERROR illegalCode=UNKNOWN_ILLEGAL_CODE requestId=...
    WARN illegal error code outside closed set; falling back to INTERNAL_ERROR illegalCode=UNKNOWN_ILLEGAL_CODE_2 requestId=...
    ```
  - 响应体 JSON 中的 `code` / `errorCode` 均被强制纠正为 `"INTERNAL_ERROR"`，文案纠正为 `"internal service error; please reference requestId for support"`。
  - **复测判定**：非法 code 无法穿透至客户端，审计告警与降级防御符合预期。

### 3.3 前端 503 猜测消解与 BFF 状态保真透传审计
- **实现核查（`src/lib/api.ts` & `src/app/api/market/route.ts`）**：
  - 重构并导出 `classifyStatus(status, detail, envelope)`：
    1. 优先以 `envelope.code` 闭集判定分类：
       - `SERVICE_NOT_CONFIGURED` $\to$ `"not-configured"`；
       - `DATABASE_UNAVAILABLE` / `UPSTREAM_UNAVAILABLE` / `INTERNAL_ERROR` / `RATE_LIMITED` $\to$ `"upstream-error"`；
       - `RESOURCE_NOT_FOUND` $\to$ `"invalid-symbol"`；
    2. 当后端返回 503 时，若包含 `code === "DATABASE_UNAVAILABLE"`，准确识别为 `"upstream-error"`，消除了此前"凡 503 必猜未配置凭据"的假定；
    3. `/api/market` BFF 代理路由消除强制覆盖 503 逻辑（`status = upstream.status === 404 ? 404 : 503` 已删除），改为 `status = upstream.status`，保真透传上游 500、502、429 等真实 HTTP 状态码；
    4. BFF 代理路由与前端客户端统一复用 `classifyStatus` 单一事实源。
- **测试核查（`tests/api-error-envelope.test.ts` & `tests/market-*.test.ts`）**：
  - `classifyStatus` 6 项独立测试覆盖各种错误码与降级组合；
  - `fetchMarketOverviewChecked` 验证 503 `DATABASE_UNAVAILABLE` 成功归类为 `upstream-error`；
  - `/api/market BFF proxy route` 验证 503 `DATABASE_UNAVAILABLE`、500 `INTERNAL_ERROR`、502 `UPSTREAM_UNAVAILABLE`、429 `RATE_LIMITED` 保留原始 HTTP 状态码，且 `code` 与 `requestId` 完整透传；
  - 校准后的 `tests/market-route.test.ts` 与 `tests/market-independence.test.ts` 全部绿灯。
  - **复测判定**：前端 503 盲猜逻辑已彻底消解，BFF 状态码保真透传成立。

### 3.4 变异拓扑漂移消除与字节不变性审计

## 4. 【负向证伪检验（D3 环）】

依据 D3（判据必须可证伪），核验以下负向证伪用例的证伪能力：

1. **变异体注入必定触发报警（N5 变异注入）**：
   - 用例：`TestN5InjectedBodyWriteTurnsP4Red`
   - 实测：当中间件恶意写入 1 字节前缀 `!` 时，P4 的 `responseDiff` 必定捕获字节漂移并判定失败，未被捕获则直接 `t.Fatal`。
2. **非法 Code 注入必定触发告警与纠偏**：
   - 用例：`TestWriteErrorAndJsonEnvelopeErrorFallbackOnIllegalCode`
   - 实测：故意传入未审计 code（如 `"UNKNOWN_ILLEGAL_CODE"`），断言系统绝不放行，必定触发 `slog.WarnContext` 并输出统一内部错误文案。
3. **覆盖率空分母证伪**：
   - 用例：`TestPctEmptyDenominatorIsNotOneHundred`
   - 实测：门禁计算在面对 0 语句的空分母时，断言返回值绝不赋 100%，杜绝虚假全绿。
