## 2. 逐条取证（实测，非推断）

### GAP-62 · `027` / `028` 两个前缀各两份

`Get-ChildItem docs/changes` 实测：

```
027-remove-cyan-border-and-boost-stream-brightness.md
027-真实Alpaca数据与涨跌幅排行.md
028-hero-badge-cleanup-top-right-i18n-expansion.md
028-前端真实行情与涨跌幅排行.md
```

**成因**：`upstream/main` 的多个合并提交反复合并 `feat/real-alpaca-data` 与 UI 分支，两侧各自用了 `027`/`028`。
**静默性**：git **不因文件名前缀相同而报冲突**——`git status` 全绿，只有**枚举文件名**才看得见。
**与本轮让位的 `035/036/038` 同族**，但收口它要动上游既有命名。

### GAP-63 · `deploy/README.md:96` 悬空指针

```
> ⚠️ **`DATABASE_URL` 现在是硬前置**（`docs/changes/027` / GAP-49）：…
```

**实测**：该行由 **W1 侧**带入（`git diff 91f5faf ORIG_HEAD -- deploy/README.md` 命中），
它想指的是 **W1 的 `027`**，而 W1 的 `027` 已 `027→035→039` 两次让位。**故它现在指向了错的文件。**
**首轮已登记**（`docs/changes/041` §3.2 末条），**本轮仍不代改**。
**建议改法**：`docs/changes/027` → `docs/changes/039`。

### GAP-64 · `docs/planning/README.md` 索引止于 `031`

该文件的「变更记录」表覆盖 `001~031`；此后新增的 `032`~`041` **不在索引里**，
读者从该文件看不出后面还有十份记录。**判据与 `docs/changes/007`「清单类陈述必须与实际枚举对拍」同族。**

## 3. 同时**澄清**一条首轮的误判（不是新 GAP）

首轮（`docs/changes/041` §3.2）把 `backend/internal/settlement/qa_ledger_test.go:524` 列为"指向不存在路径"。

**本轮实测：该判断不成立于合并后**——

| 事实 | 实测 |
| --- | --- |
| 该行在 merge-base `91f5faf` 上**已存在** | 非 W1 引入 |
| 它指 `docs/changes/027 §5.7` | 指**上游的** `027-真实Alpaca数据与涨跌幅排行.md` |
| `docs/changes/027` 在**合并后的树**里存在吗 | **存在**（上游的 `027-remove-cyan…` 与 `027-真实Alpaca…` 都在） |

**教训（记在此以免再犯）**：**"某路径在 W1 单边检出里不存在" ≠ "合并后不存在"。**
判"悬空"必须问「**合并后的树里有没有它**」，而不是「我这边的检出里有没有」。
