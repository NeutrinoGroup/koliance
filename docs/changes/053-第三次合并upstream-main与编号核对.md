## 2. `docs/GAP台账.md` 的三处冲突：各怎么解

三处**都不是二选一**，两侧内容**全部保留**。

### 2.1 冲突一（`:36-40`）· §1 的「§5 小节索引行」

| 侧 | 该行的尾部 |
| --- | --- |
| HEAD（#34 登录态轮） | … §5.9（GAP-65~71）· **§5.11 登录态同步轮（issue #34）新开 GAP-73** |
| `upstream/main`（#36） | … §5.9（GAP-65~71）· **§5.10 后端覆盖率门禁与随之暴露的一条（GAP-72，`docs/changes/048`）** + 「§5.10 加入时又对拍了一次」 |

**解法**：**取并集成一行**，两侧的新增项**都在**（§5.10 与 §5.11 并列），
并把该行自称的"对拍结论"**改成与文件实际枚举一致**：

- 原两侧都写「输出 §5.1~§5.10」/「§5.1~§5.11」——**合并后两侧都不再成立**；
- 改为**逐项可复跑**的陈述：**`Select-String '^### 5\.\d'` 输出 §5.1~§5.11，共 11 节，与本行逐一对应**；
- 并**显式点出 §5.12 不在此文件**（它在未合并分支 `docs/error-handling-adr` 上），
  免得下一位读者把"并集有 12 节"与"本文件有 11 节"当成矛盾。

> **为什么必须改这句话**：它是**自指陈述**（说的是"本行与文件自身枚举一致"），
> **错了不会响**——没有任何测试会失败（`AGENTS.md` §8 的「自指陈述」条）。
> 上一版把「前一版只列到 §5.6」写在那里，**本轮合并后又差一点复现同一个错**。

### 2.2 冲突二（`:213-217`）· §1 状态总览表的**表尾行**

| 侧 | 追加的行 |
| --- | --- |
| HEAD | `| **GAP-73** | 登录态的行为级判据只覆盖纯函数那一半 … |` |
| `upstream/main` | `| **GAP-72** | internal/liquidation 有测试文件却仍是 0.0% 覆盖率 … |` |

**解法**：**两行都保留**，且**按号序落位**（`GAP-72` 在 `GAP-73` 之前），表体**保持连续**。
落地后实测：§1 状态总览表**共 71 行**，**无重号**，尾部为 `…GAP-70 · GAP-71 · GAP-72 · GAP-73`。

> **一处落地时自己踩到的坑（照实记）**：我最初把「GAP-72 取号注」插在 `GAP-72` 行**之后**，
> 结果它**插进了表格内部**，把表从 `GAP-73` 处**截断**（`GAP-73` 落到表外，表尾成了 `GAP-72`）。
> **靠"按内容定位"的对拍脚本抓到**（不是靠肉眼读）：脚本按 `| **GAP-72** |` 前缀收集表行时，
> `GAP-73` 不再被收进同一个表。**已改为把该注移到表尾之后**。
> **教训**：往 Markdown 表里插内容，**必须用"表行枚举"来验证**，肉眼读表格看不出来。

### 2.3 冲突三（`:1140-1318`）· **一整节**：§5.11 与 §5.10

| 侧 | 该节 | 内容 |

## 3. 编号核对（D4 / `AGENTS.md` §6）——**本次无撞号，未重编任何号**

### 3.1 核对口径（实测，建议后续沿用）

**逐 ref** 扫，**不用 `git log --all --name-only`**：

```
git -C <wt> for-each-ref --format="%(refname)" refs/heads refs/remotes     # → 34 个 ref
# 逐 ref：
git -C <wt> grep -h -o -E "GAP-[0-9]+" <ref> -- docs/
git -C <wt> grep -h -o -E "### 5\.[0-9]+" <ref> -- docs/GAP台账.md
git -C <wt> ls-tree -r --name-only <ref> -- docs/changes/
```

> **为何不用 `git log --all --name-only`**：它默认**简化 merge**，
> **不能据"列不出"判定文件/号不存在**——**口径本身不可靠，故不用**（本轮已把它从口径里剔除）。
> **另一条实测出来的坑**（`docs/error-handling-adr` 的取号注已记过一次）：
> 文件里**不只有"登记"会命中 `GAP-\d+`**——正文里的**区间字面量与交叉引用**（如「`GAP-65~71`」）
> 也会命中。故并集只用于**判"某号是否出现过"**，**不用于判"某号是否被登记"**。

### 3.2 实测结果（2026-10-12T11:46Z 快照）

| 项 | 实测值 |
| --- | --- |
| ref 总数 | **34**（`refs/heads` + `refs/remotes`） |
| `GAP-` 并集 | **`GAP-1` … `GAP-76`**，**连续无洞**（**76 个号 / 76 个不同值**） |
| `### 5.x` 并集 | **`§5.1` … `§5.12`**，**无重号** |
| 本分支（`4b3464c`）持有 | `GAP-70/71/73` · `§5.1`~`§5.9` + `§5.11` |
| `upstream/main`（`22fa845`）持有 | `GAP-70/71/72` · `§5.1`~`§5.10` |
| `docs/changes/` 全 ref 最大号 | **`052`**（在 `fix/wallet-first-login`） |
| **`053`** | **全 ref 零命中**（`git grep -l 053 <34 refs> -- docs/` → 空） |

**结论：`GAP-73` 与 `GAP-72` 相邻但不重叠，`§5.11` 与 `§5.10` 同理 → 本次合并无同号两义。**
**故本次是 union 合并，未让号、未重编任何号**——这一点与前两轮（`GAP-51/52`、`GAP-57/58` 两次撞车）**不同**。
