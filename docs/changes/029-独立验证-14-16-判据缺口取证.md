### 3.1 F2 —— 实现方 #14 负向判据的洞（**本次最重要的发现**）

`market_test.go:115` 的禁止子串表是
`{"150", "TSLA", "realtimePrices", "gainers", "feedId"}`。F2 的注入**一个都没命中**，实测：

```
### (a) MY test vs a 503-carrying-a-price ###

    market_edge_qa_test.go:187: GET /api/v1/market/movers: top-level keys = [error lastKnownRegularMarketPrice], want exactly [error]
    market_edge_qa_test.go:190: GET /api/v1/market/movers: refusal body contains JSON numbers [999.99] — a refusal carries no number
```

**为何这是「判据夹缝」而非「假想敌」**：这条注入**同时**满足实现方现有的**每一条**断言 ——

对 issue #14 而言这正是要防的形态 ——「503 的响应体里零价格字段」是契约，子串表只是它的一个近似。

## 4. 发现的判据缺口（有/无都给出依据）

### 4.1 **GAP-55（🟡 P2）—— 凭据的「配置」有两套定义，三条路径给出三种状态码**

`config.Config.AlpacaConfigured()`（`config.go:58`）比较**原始** env 值；
`PriceOracle`/`AlpacaClient` 的 `Configured()`（`price_oracle.go:79`、`alpaca_client.go:70`）
对值做 `TrimSpace`。于是 `ALPACA_API_KEY="   "`（Replit/Heroku 式 env 编辑器很容易产生）
**通过 503 门禁**，然后在 handler 内部失败。实测：

```
market_edge_qa_test.go:330: GAP: whitespace-only credentials →
  map[/api/v1/market/movers:502 /api/v1/market/overview:500 /api/v1/market/prices:502]
  (503 was the contract; overview answers 500 while the two data endpoints answer 502 — the three disagree with each other)
```

- **安全性质仍成立**（响应体里**零价格字段**，同一用例逐条断言了）；
- 但**诊断语义错了**：502 告诉调用方「上游在闹脾气」，500 告诉它「这个服务崩了」，
  而事实是「**这个部署根本没配置**」——恰恰是 issue #14 要消除的那种误导。
- 且**三条路径互相不一致**（502/502/500），而它们的契约是同一个。
- 这正是 D4「两处不同成熟度的定义」的形态：`"configured"` 一词在两处指称不同的谓词。

**建议**：`Config.AlpacaConfigured()` 改为与 oracle 同口径（trim 后比较），
或在 `Load()` 中对 env 值做一次 trim。**本次未改生产代码**，只留下**刻画性用例**
`TestIndyWhitespaceCredentialsPassTheGateButNotTheOracle`（当前绿、把现状钉住；
一旦两处口径统一，该用例按设计**转红**并要求改断 503 —— 用例内写明了这一点）。

### 4.2 **GAP-56（🟡 P2）—— `GetMarketOverview` 吞掉 positions/prices 错误，把「问不到」变成「没动」**

实现方自己点名了这条（`docs/changes/027` 末段之三）。本次**实测其后果**：

```
market_edge_qa_test.go:857: GAP: overview answers 200 with "realtimePrices":null and an empty movers board;
  the error text ("boom" / "subscription does not permit querying recent SIP data") reaches no caller
```

即：**同一份上游故障**，在 `/api/v1/market/movers` 上是 **502**（响亮），
在 `/api/v1/market/overview` 上是 **200 + `realtimePrices:null` + 空 board + `unrankedCount:0`** ——
而后者的语义与「市场今天一个标的都没动」**逐字节相同**。
`Movers` 的注释写着「unranked 计数是为了让『问不到』区别于『没动』」，但 overview 这条路径**把两个错误都丢了**，
于是这个区分在**该响应形状**上失效。

**边界（不夸大）**：前端 `MarketTerminal.tsx:158` 是四路并发且**各自独立**持有 failure 状态，
`pricesRes`/`moversRes` 的 503 会各自点亮 `pricesFailure`/`moversFailure`，
所以**当前前端不会因此显示假行情**。缺口在**后端契约**：任何只读 `overview.realtimePrices` 的调用方
（现成的或将来的）无法区分这两件事。

### 4.3 一条**未构成缺口**但值得记录的实测：`AgeMS` 的 `omitempty`

`ProbeResult.AgeMS` 声明为 `json:"ageMs,omitempty"`。同一毫秒内命中缓存时 `AgeMS == 0`，
字段被**整个省略** —— 于是 `"cached":true` 而**没有** `ageMs` 是合法编码，不是缺陷。

**这是本次真实踩到的**：我的并发缓存用例断言了 `ageMs` 必在，于是**间歇性变红**（一次全包运行里 24 个 worker 里 6 个红）。
定位后的结论是**我的断言过严**，不是产品缺陷；已改为在断言前 `time.Sleep(5ms)` 让年龄可测（§2 的 5 次连跑证明不再抖）。
**记录在此以免后人重复踩**：`docs/changes/027` 把 `cached`/`ageMs` 描述为
「保证『这条判断是**近期**真实调用的结果』这点仍然可查」—— 严格说 `ageMs` 缺席时
读者只能知道「≤1ms 前」，**这是足够的信息，但文档没写**。

### 4.4 一处**未击穿**，如实标注证据级别

`rankMovers` 的 symbol tie-break 在**HTTP 路径**上抓不到差异（F4 注入后我的
`TestIndyMoversIsByteStableUnderConcurrency` **仍绿**）：
因为 `PriceChange` 的循环是 `for _, sym := range want`（**切片**，非 map），
`page.Bars[sym]` 只是查表 —— 交给 `RankMovers` 的顺序本就是确定的。
所以该端点的字节稳定性目前是**由调用方的迭代方式顺带保证的**，
tie-break 是给**直接调用方**（如 `MoversFromPrices` 的将来调用者）与
`Mock`/上游形状变化的**防御**。级别：**已实测（注入后不变红）**，非推断。
