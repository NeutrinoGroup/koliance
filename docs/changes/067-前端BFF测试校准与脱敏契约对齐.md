## 1. 背景与目标

根据后端真实 ADR-006 统一报错规范及脱敏铁律（`CodeServiceNotConfigured`）：
- 严禁在对外 API 响应中泄露内部敏感凭据名称（如 `ALPACA_API_KEY` / `ALPACA_API_SECRET`）；
- 后端错误响应严格统一为 ADR-006 封闭集信封结构：
  ```json
  {
    "code": "SERVICE_NOT_CONFIGURED",
    "error": "service credentials are not configured on this deployment",
    "requestId": "..."
  }
  ```
- 此前前端测试 `tests/market-route.test.ts:108-126` 及 `tests/market-movers.test.ts:39-53` 仍在使用历史遗留的未脱敏 mock（`error: "market data unavailable: ALPACA_API_KEY/ALPACA_API_SECRET are not configured"`），并断言了 `expect(body.error).toContain("ALPACA_API_KEY")`。

为了彻底消除测试层对过时契约的残留依赖，保持前后端契约单一事实源（D4）与测试断言对真实生产 ADR-006 行为的精确保真，执行本次测试契约校准。

---

## 2. 详细修改清单

### 2.1 `tests/market-route.test.ts`
- **升级 mock 数据源**：
  将 `when the gateway has no credentials (503)` 分支下的 mock 响应升级为生产真实 ADR-006 信封：
  ```ts
  jsonResponse(503, {
    code: "SERVICE_NOT_CONFIGURED",
    error: "service credentials are not configured on this deployment",
    requestId: "req-test-123",
  })
  ```
- **升级测试断言**：
  - 验证 `res.status === 503`；
  - 验证 `body.reason === "not-configured"`；
  - 验证 `body.code === "SERVICE_NOT_CONFIGURED"`；
  - 验证 `body.requestId === "req-test-123"`；
  - 验证 `body.error` 包含 `"service credentials are not configured"`（消除对敏感词 `"ALPACA_API_KEY"` 的依赖断言）。

### 2.2 `tests/market-movers.test.ts`
- **升级 mock 数据源与测试断言**：
  将 `classifies the gateway's 503 as not-configured and keeps its words` 用例中的 mock 响应升级为生产真实 ADR-006 信封：
  ```ts
  jsonResponse(503, {
    code: "SERVICE_NOT_CONFIGURED",
    error: "service credentials are not configured on this deployment",
    requestId: "req-test-movers-503",
  })
  ```
  - 验证 `res.ok === false`；
  - 验证 `res.reason === "not-configured"`；
  - 验证 `res.code === "SERVICE_NOT_CONFIGURED"`；
  - 验证 `res.requestId === "req-test-movers-503"`；
  - 验证 `res.detail` 包含 `"service credentials are not configured"`。
