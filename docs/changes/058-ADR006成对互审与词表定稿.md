## 1. 定稿结论概要

1. **成对互审收敛（GAP-74 条件 ①②③ 达成）**：
   - `system-architect` 与 `sec-auditor` 完成交叉互审并定稿，零未决分歧。
   - **受众分级**：调用方视图严格受限于闭集错误信封 `{"error", "code", "requestId"}`，阻断 §3.4 七类敏感项；运营方视图（`/healthz` 等）仅允许配置项变量名与布尔状态，严禁明文凭证/DSN/未脱敏 URL。
   - **安全审计新纳入 3 个 P0 泄漏点（02 环必改）**：`SEC-P0-1`（`health.go` 探针 URL 剥离 `?key=` 与收敛 panic 文案）、`SEC-P0-2`（`router.go:519` Alpaca 256B 原文覆写并记日志）、`SEC-P0-3`（`reqlog.go` 增强脱敏正则与前缀匹配）。

2. **核心架构机制**：
   - **`*errSlot` 堆指针槽位**：中间件注入 `&errSlot{}`，`recordError(r, err)` 直接写槽位指针，根除 context 浅拷贝丢失 `rawErr` 风险。
   - **四类出口总数实测收敛**：
     - 出口 1：`jsonError` 共 51 处（`router.go` 47 处 + `middleware.go` 4 处）替换为 `writeError`；
     - 出口 2：`router.go:670-675`（`verifier/verify` 手写 map）统一接入 `recordError` 与闭集信封；
     - 出口 3：`router.go:703-810`（`jsonEnvelope` 错误分支 12 处）统一使用 `jsonEnvelopeError`；
     - 出口 4：`router.go:519`（`ExecuteTrade` 200 OK 伪成功错误分支）调用 `recordError` 并覆写业务文案。

3. **12 个 ErrorCode 闭集枚举与唯一固定文案（P1 闭集 / P3 全可达）**：
   - `INVALID_REQUEST` (400): `"invalid request parameters or payload format"`
   - `INVALID_PROOF` (400): `"cryptographic proof verification failed: invalid proof"`
   - `UNAUTHORIZED` (401): `"authentication required or credentials invalid"`
   - `QUOTA_EXHAUSTED` (403): `"developer quota or free claim limit exhausted"`
   - `RESOURCE_NOT_FOUND` (404): `"requested resource or market symbol not found"`
   - `METHOD_NOT_ALLOWED` (405): `"HTTP method is not allowed for this endpoint"`
   - `RATE_LIMITED` (429): `"request rate limit exceeded; please retry later"`
   - `INTERNAL_ERROR` (500): `"internal service error; please reference requestId for support"`
   - `VERIFIER_UNAVAILABLE` (501/503): `"proof verifier is not configured or scheme is not implemented"`
   - `UPSTREAM_UNAVAILABLE` (502): `"upstream market data provider failed to respond"`
   - `DATABASE_UNAVAILABLE` (503): `"database is unavailable; this endpoint requires a durable store"`
   - `SERVICE_NOT_CONFIGURED` (503): `"service credentials are not configured on this deployment"`

4. **测试判据冲突消解序列（C1~C5）**：
   - C1/C2：拒绝体键闭集断言由 `["error"]` 升级为 `["code", "error", "requestId"]`，配负向对照；
   - C3：`/api/v1/market/trade` 503 断言改为匹配 `SERVICE_NOT_CONFIGURED` 且不含 env 键名，诊断端点保留诊断断言；
   - C4/C5：文案含关键词自然兼容既有 `DATABASE_UNAVAILABLE` / `VERIFIER_UNAVAILABLE` 断言。
