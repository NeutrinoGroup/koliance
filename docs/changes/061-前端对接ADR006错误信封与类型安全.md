## 1. 改动背景与目标

依据 ADR-006（后端统一报错处理体系：原始报错留痕 · 向上游说业务语言）及总控派发任务指令（Step 2.3 前端错误信封对接）：
1. **查阅 ADR-006 标准信封**：
   后端标准错误响应返回 `{ code: string, error: string, requestId: string }`（以及针对 developer / agent 出口兼容的 `errorCode` 与向下兼容字段）。
2. **重构与类型加固 `src/lib/api.ts`**：
   - 导出 `ApiErrorEnvelope` 接口：`{ code?: string; error?: string; requestId?: string }`。
   - 增加防御性解析方法 `parseApiError(res: Response)`，不假定非 2xx 响应为合法 JSON，安全提取 `error`、`code`/`errorCode` 以及 `requestId`（支持从 `X-Request-Id` 响应头兜底）。
   - 导出强类型接口 `ExecuteTradeResult`、`ClosePositionResult`、`StripeCheckoutResult`、`MicropaymentResult`。
   - 改造 `executeMarketTrade`：在非 2xx（如 400 `INVALID_REQUEST`、503 `SERVICE_NOT_CONFIGURED`）以及 200 OK 伪成功（`success: false`）路径下，完整提取并向上游暴露 `{ error, code, requestId }`；网络异常时安全降级。
   - 改造 `closeMarketPosition`：完整提取非 2xx 响应中的 `{ error, code, requestId }`。
   - 改造 `marketGet` 与 `MarketFetch<T>`：失败分支保留 `code` 与 `requestId`。
   - 改造 `createStripeCheckout` 与 `authorizeMicropayment`：规范返回类型并承接信封字段。
3. **前端消费组件与展示**：
   - `src/components/MarketTerminal.tsx`：
     - `handleClosePosition`：平仓异常 Toast 中呈现 `[code]` 与 `(Req ID: requestId)`；
     - `handleExecuteAlpacaTrade`：未成交 Toast 中呈现 `[code]` 与 `(Req ID: requestId)`；
     - `fetchMarketData`：400 校验错误时呈现 `[code]` 与 `(Req ID: requestId)`；
     - `FailureNotice`：支持渲染 `code` 与 `requestId`；
     - 增加 `quoteEnvelope` 与 `accountEnvelope` 状态跟踪。
   - `src/app/api/market/route.ts`：BFF 代理层在网关拒绝时，将上游信封中的 `code` 与 `requestId` 透传给下游。
   - `src/components/AgentCardTerminal.tsx`：Stripe 错误与 Visa 拒付拦截提示中保留并拼接 `code` 与 `requestId`。
4. **测试与本地验证**：
   - 增加独立单元测试文件 `tests/api-error-envelope.test.ts`（15 个用例），全覆盖测试解析、网络函数、BFF 路由代理与错误信封保真。
   - 运行 `npx tsc --noEmit`（零错误）与 `npm test`（25 个测试文件、292 个用例全部通过）。

## 2. 详细实现清单与设计决策

### 2.1 `src/lib/api.ts`
- **定义并导出 `ApiErrorEnvelope`**：
  ```ts
  export interface ApiErrorEnvelope {
    code?: string;
    error?: string;
    requestId?: string;
  }
  ```
- **安全信封解析 `parseApiError`**：
  防御性检查 `res.json()`，解析 `code` 与 `errorCode`、`error` 与 `requestId`；若响应体无 `requestId` 则安全检查 `res.headers?.get("X-Request-Id")` 进行头回退。
- **扩展 `MarketFetch<T>`**：
  在 `{ ok: false; reason: MarketFetchReason; detail: string }` 基础上追加可选的 `code?: string; requestId?: string`。
- **强类型与信封保真**：
  - `executeMarketTrade` -> `Promise<ExecuteTradeResult>`
  - `closeMarketPosition` -> `Promise<ClosePositionResult>`
  - `createStripeCheckout` -> `Promise<StripeCheckoutResult>`
  - `authorizeMicropayment` -> `Promise<MicropaymentResult>`

### 2.2 `src/app/api/market/route.ts`
- 代理网关拒绝时，提取 `upstream` 响应体中的 `code` 与 `requestId`（支持 `upstream.headers?.get("X-Request-Id")`），通过 `refuse(...)` 附加在响应 JSON 中。

### 2.3 `src/components/MarketTerminal.tsx` 与 `AgentCardTerminal.tsx`
- 在各业务报错入口将错误码与请求追踪 ID 拼接进用户可视的 Toast 与错误通知组件，避免信息截断与排查黑盒。

### 2.4 `tests/api-error-envelope.test.ts`
- 覆盖 ADR-006 12 错误码标准信封解析、developer 路由 `errorCode` 兼容、header 回退、非 JSON 降级、交易/平仓/Stripe/Visa 等各调用函数，以及 BFF 路由的端到端透传。
